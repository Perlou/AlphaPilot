# AlphaPilot 诚实性宪章（Honesty Charter）

> 状态：生效 · 对应 spec §8 · 最后更新 2026-11-08
>
> 量化研究最大的敌人不是没找到 alpha，而是**以为自己找到了**。
> 本宪章列出 AlphaPilot 在设计上**强制执行**的诚实性原则。每一条都对应一个具体的实现机制和一个可验证的测试或评测。**任何功能都不得削弱这些原则**；如果确实需要放宽，必须新写一条 ADR，说明理由并获得批准。

---

## 原则一：结论由代码计算，不由模型断言

- **规则**：报告、日报、审批卡片里出现的每一个数字，都必须来自数据库中某条记录（trial、backtest、nav 或 alert）的字段。
- **机制**：
  1. LLM 写报告时，数字一律用占位符表示，例如 `{{trial:42.icir}}`，再由渲染器填入真实数值；
  2. 渲染后运行 `verify_numbers`，确认报告中的每个数字都能在事实表中找到来源；
  3. faithfulness 检查不通过的报告**不能提交审批**。
- **验证**：agent 测试“编造数字被拦截”；eval 指标“faithfulness 通过率”。

## 原则二：每一次看数据都要计数

- **规则**：只要接触了数据的因子评估，就算一次 trial。trial 只能追加，不能删除，计数项目内全局累计、永不清零。被丢弃的、失败的、外部 MCP 客户端产生的 trial 都要计入。
- **机制**：
  - `trials` 表上有 trigger，禁止 UPDATE 和 DELETE；
  - 多重检验的 N 取自全局 ledger；
  - `stats.correct` 只从 ledger 读取，不接受调用方传入的 p 值。
- **验证**：integration 测试验证 trigger 生效；unit 测试验证 N 的口径。

## 原则三：样本外只能用一次

- **规则**：
  - HOLDOUT 区间必须经过人工审批才能评估；
  - 每个表达式只能评估一次，近似表达式（canonical_hash 相同，或相关性超过 0.95）视为同一个；
  - HOLDOUT 的结果**永远不进入**之后任何 planner 或 coder 的上下文。
- **机制**：
  - `holdout.evaluate` 不在任何 MCP profile 中暴露，调用时必须带已批准的 approval_id；
  - 所有工具的输出都会脱敏，去掉 holdout 区间的日期、股票代码和收益。
- **验证**：agent 测试“越权调用 holdout 触发 GuardrailError”；eval 指标“成功越权次数 = 0”。
- **受控泄漏（明确接受）**：因子入库要先经过 holdout 判定和人工决策，所以“某因子在 production 中”本身带有 1 bit 的 holdout 信息。我们把人工决策之后的因子库视为公开知识，接受这部分泄漏。作为对策，`registry.list` 对 Agent 和 MCP 只返回 production 因子和基线因子的名称与表达式，不返回状态区分、来源 trial 或 holdout 指标。

## 原则四：如实标注证据等级

- **规则**：每个结论都要标注 `evidence_level`：
  - `IS`：样本内；
  - `PSEUDO_OOS`：HOLDOUT 区间结束早于所用模型中最晚的知识截止日。LLM 可能“见过”这段行情，所以这不是真正的样本外；
  - `TRUE_OOS`：批准之后的真实时间，即 forward 模拟盘。只有这一级算真正的验证。
- **机制**：
  - 每个模型在配置中登记 `knowledge_cutoff`；官方没有公布时，**保守地取发布日期**；
  - 报告和审批卡片必须显示证据等级和污染警告；
  - planner 的上下文里不出现日期和股票代码。
- **验证**：unit 测试覆盖 evidence_level 计算；前端测试验证警告横幅一定会显示。

## 原则五：审批必须是真审批

- **规则**：
  - 存在 hard_fail（前视检测失败、覆盖率不足、与已有因子高度相关、校正后不显著）的候选**不能被批准**；
  - 批准时必须填写理由；
  - 审批人与发起人是同一人时标记为 `self_approved`；
  - Agent 和工具都不能审批。
- **机制**：
  - API 收到对 hard_fail 候选的批准请求时返回 409，前端的批准按钮同时禁用；
  - 所有决策写入 `audit_log`，用哈希链防止篡改。
- **验证**：API 测试；审计链校验测试。

## 原则六：合成数据不得冒充真实数据

- **规则**：数据源失败时可以回退到合成数据，但合成数据**必须一路被标记**。基于合成数据得出的因子不能上线。
- **机制**：
  - `is_synthetic` 记录在数据快照中，并传递到 trial、backtest 和 report；
  - promote 接口会拒绝合成数据快照上的因子；
  - UI 显示红色横幅。
- **验证**：unit 测试和 API 测试。

## 原则七：主动披露偏差

- **规则**：报告附录必须自动列出所用数据的已知偏差：
  - 使用当前成分股带来的幸存者偏差；
  - 使用当前行业分类；
  - 停牌和缺失值的处理方式；
  - 复权口径：收益只用 Sina 等比复权，**不用**东财的加减法复权；
  - 成本假设。
- **机制**：`data_snapshots.known_biases` 字段，由报告模板强制渲染。
- **验证**：报告模板测试。

## 原则八：阴性结论也是成果

- **规则**：预算用完仍没有找到通过检验的因子，是正常且有价值的结果。报告必须包含“未通过的假设及原因”一节，不允许为了拿出成果去放宽阈值。
- **机制**：
  - 预算耗尽时转入 report 节点，而不是报错退出；
  - critic 的阈值来自配置，并记录在 run_manifest 中；单个 run 内不能修改。
- **验证**：agent 测试“预算耗尽产出阴性报告”；eval 指标“零信号面板错误发现率”。

## 信任边界

上述原则覆盖 AlphaPilot 的**所有系统入口**：Agent、MCP、API 和 CLI。

- CLI 回测默认只评估 builtin 或 production 因子，并截断到 IS 区间末尾。要访问封存窗口（HOLDOUT 或 RESERVED），必须由 admin 显式加开关，并且这次访问同样写入 ledger 和审计日志。
- 在 Python 里直接 import 内核库计算，属于**信任边界之外**，系统无法阻止，因为有代码权限的人总能自己算。但这类结果在 ledger 中没有 trial 记录，**不能注册，也不能 promote**。也就是说，系统保证的是“进入因子库和生产环境的东西都经过了完整的诚实性流程”，而不是“没有人能看到数据”。

## 系统级诚实性指标

AlphaPilot 用两个评测来检验整套研究流程是否诚实：

| 评测 | 方法 | 期望 |
|---|---|---|
| **零信号面板 FDR** | 在截面上打乱收益（或用纯噪声）构造面板，跑 N 个完整的研究 run | 被批准的因子数接近 0，且不超过阈值（见 `docs/design/testing-and-evals.md`） |
| **植入因子召回** | 在合成面板中植入已知强度的信号，比如低波动溢价和短期反转 | 强信号能被找回，弱信号允许漏检，但不允许“发现”没有植入的信号 |

**零信号面板上找不出“显著因子”，这套系统的阳性结论才可信。**

## 设计约束清单（代码评审时逐条核对）

- [ ] 新增的工具是否计入 trial？是否需要加入护栏？输出是否已脱敏？
- [ ] 新增的 LLM 上下文里是否混入了日期、股票代码或 holdout 信息？
- [ ] 新增的数字展示是否来自数据库字段，而不是 LLM 的文本？
- [ ] 新增的阈值是否放在配置中，并且会写入 manifest？
- [ ] 新增的数据源是否传递了 `is_synthetic` 和 `known_biases`？
- [ ] 新增的写操作是否进入了 audit_log？
