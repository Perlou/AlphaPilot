# ADR-0004：Agent 不下单，只产出可验证的研究成果

- 状态：已接受
- 日期：2026-11-08

## 背景

“多个 LLM Agent 辩论后给出买卖决策”这类项目（例如 TradingAgents）演示效果很好，但有一个**无法回避的方法论缺陷**：LLM 的训练数据覆盖了回测区间，模型“知道”后来发生了什么，所以回测结果天然被污染，无法给出可信的业绩证据。此外，LLM 输出不可复现（新模型已不支持 temperature=0），审计困难，还有幻觉风险。

qtc 课程 Phase 10 第 10 课专门讨论过这个陷阱。

## 决策

**LLM 只做三件事：提出想法（假设）、写代码（DSL 表达式）、写文字（报告和诊断）。**

- 所有判定由**确定性代码**完成：IC 检验、多重检验校正、DSR、前视检测、相关性过滤。
- 所有会影响资金的动作都需要**人工审批**：使用 holdout、因子入库、上线生产、下线、运维动作。
- 交易由确定性的每日流水线按 `strategy_version` 执行。Agent 无法直接下单，也无法修改持仓。
- 监控 Agent 只能**提出**运维建议；kill-switch 是确定性代码，Agent 无法解除。

## 后果

- ✅ 因子是公式，可以在任意数据上复算，所以研究结论可复现、可审计。
- ✅ LLM 的污染被限制在“想法来源”这一层，可以用 evidence_level 如实标注。
- ✅ 演示和面试时，“为什么不让 LLM 直接交易”本身就是一个有深度的亮点。
- ⚠️ 演示效果不如“AI 自动交易”那样直观，需要用 Web 控制台的实时轨迹和审批中心来弥补。
