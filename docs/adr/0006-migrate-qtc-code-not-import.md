# ADR-0006：qtc 代码迁移重构进本仓库，不跨仓库 import

- 状态：已接受
- 日期：2026-11-08

## 背景

AlphaPilot 要复用 qtc 课程中的大量代码：数据层、因子 DSL、统计工具、mini_quant、mini_trader。这些代码目前分散在各个课程目录里，由 `mini_quant/_paths.py` 修改 `sys.path` 拼接起来，依赖 phase-4、7、8、10、13 下的模块，而且没有打包。

## 决策

- 把需要的代码**迁移**到 `src/alphapilot/` 下对应的子包，改为正常的包内 import，删除 `sys.path` hack。
- 迁移时只做**有限重构**：补类型注解、统一命名、修已知问题、拆分过大的文件。**不改变算法和数值行为**，用 golden 测试保证结果与 qtc 一致（误差 1e-8 以内）。
- qtc 的测试一起迁移；qtc 仓库本身保持不动。
- 提供 `ap data import-qtc --from ../qtc/data/cache`，用于导入 qtc 已有的数据缓存，避免重新下载。

## 后果

- ✅ AlphaPilot 可以独立安装、部署和测试。
- ✅ 迁移本身是一次重要的工程化练习，也便于在面试中讲解。
- ⚠️ 两个仓库之后会各自演进，qtc 的后续修改不会自动同步过来。可以接受，因为 qtc 是课程归档。
- ⚠️ golden 测试依赖 qtc 的数据缓存；缓存不存在时测试会跳过并给出明确提示，不能让测试失败显得像是通过了。
